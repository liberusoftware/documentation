# Liberu end-user interface guides

These guides describe what people experience in an application powered by a Liberu project: public websites, authenticated portals, staff workspaces, and mobile apps. They are product contracts for behavior and experience, not framework implementation manuals.

## Start here

- [Web and mobile experience standard](WEB-AND-MOBILE.md) — shared visual language, responsive shells, journeys, states, accessibility, and developer acceptance.
- [Project guides](projects/README.md) — choose a product or platform experience.
- [Module guides](modules/README.md) — find end-user behavior for every documented feature module.

A module guide answers: who uses it, what they see, what the main journey feels like, how web and mobile differ, what success/error/offline states mean, and what an installed application must make observable. Link back to the canonical developer scope when implementation detail is needed.

## Experience promise

Every public interface should make the next useful action obvious, explain why an action is unavailable, preserve work during interruption, respect consent and accessibility, and show trustworthy status for queued or provider-dependent work.
