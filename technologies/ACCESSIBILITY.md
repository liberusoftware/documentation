# Web accessibility technology reference

Accessibility is a product requirement across all Liberu presentation layers, not a final visual check. Follow WCAG 2.2 AA where applicable and test with keyboard navigation, reduced motion, zoom, screen readers, and automated checks.

## Delivery checklist

- Use semantic HTML and native controls.
- Provide visible focus, labels, instructions, validation summaries, and non-color status indicators.
- Manage focus after navigation, dialogs, validation failures, and dynamic updates.
- Respect reduced-motion, contrast, text resizing, pointer target, and RTL requirements.
- Test permission-denied, empty, loading, queued, failure, and recovery states.

Official references: [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [WAI tutorials](https://www.w3.org/WAI/tutorials/), [ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/), [axe-core](https://github.com/dequelabs/axe-core), and [Lighthouse accessibility](https://developer.chrome.com/docs/lighthouse/accessibility/).
