## Read source availability correctly

A capability, a source directory, an installable package, and a published release are different things. Ecommerce currently contains application-owned domain models, services, controllers, policies, Filament resources, routes, views, migrations, and tests. Package extraction can relocate these without changing the product catalogue. Do not remove a documented module because its implementation is outside `modules/`.

The root Composer manifest declares `liberusoftware/project-ecommerce-laravel-filament` as a project, while the root npm manifest is private and builds application assets with Vite. Neither is evidence of an independently published npm presentation module. See [composer.json](https://github.com/liberusoftware/project-ecommerce-laravel-filament/blob/af5a2b29c9c26ba89c97b9daccbb3facf20a8c2f/composer.json) and [package.json](https://github.com/liberusoftware/project-ecommerce-laravel-filament/blob/af5a2b29c9c26ba89c97b9daccbb3facf20a8c2f/package.json).

## Current API integration

The route provider applies the `/api` prefix to [routes/api.php](https://github.com/liberusoftware/project-ecommerce-laravel-filament/blob/af5a2b29c9c26ba89c97b9daccbb3facf20a8c2f/routes/api.php). That route file includes authenticated product, collection, cart, customer, order, refund, return, dropshipping, and outbound-webhook operations. It also registers a GraphQL endpoint. These are application routes: the generic planned `/api/v1/ecommerce/...` examples in adapter specifications do not establish those routes as implemented.

Customer order reads are separate from staff refund and status actions. The route comments identify controller-owned role checks on several staff operations, so checking `auth:sanctum` alone is insufficient to understand authorization. Read controller and policy code when integrating. The code-first storefront GraphQL schema in [app/GraphQL/StorefrontSchema.php](https://github.com/liberusoftware/project-ecommerce-laravel-filament/blob/af5a2b29c9c26ba89c97b9daccbb3facf20a8c2f/app/GraphQL/StorefrontSchema.php) exposes catalog queries and user-scoped cart/order operations. Do not assume the REST and GraphQL field names or response envelopes are interchangeable.

For a Next.js storefront, build a typed transport against the observed routes/schema and explicitly choose the session integration. Reuse Laravel checkout calculations and stock handling. For Inertia, preserve the server-owned navigation protocol. Neither adapter should recalculate authoritative prices, eligibility, or tax from browser-submitted totals.

## Checkout implementation and recovery

[app/Services/CheckoutService.php](https://github.com/liberusoftware/project-ecommerce-laravel-filament/blob/af5a2b29c9c26ba89c97b9daccbb3facf20a8c2f/app/Services/CheckoutService.php) provides shared purchasing checks, gateway acceptance, coupon resolution and availability checks, inventory reservation/release, payment capture, download grants, and dropship queueing. [app/Services/HeadlessCheckoutService.php](https://github.com/liberusoftware/project-ecommerce-laravel-filament/blob/af5a2b29c9c26ba89c97b9daccbb3facf20a8c2f/app/Services/HeadlessCheckoutService.php) orchestrates these for the persistent authenticated cart.

The headless flow loads cart items for the user, validates purchasability and payment gateway, resolves a stored shipping quote, recalculates coupon and tax, and creates the pending order with stock reservation inside a database transaction. It then captures payment, advances the order to paid, grants downloads, optionally queues dropshipping, and clears the cart. The explicit payment-failure branch releases stock, transitions the order to failed, and raises a checkout error. Other failure windows still need behavior review; this sequence is not a claim of general exactly-once processing.

The source currently uses floating-point casts and rounding for several checkout calculations. The precise-money requirements in the target architecture are therefore a design improvement to verify, not a description of completed implementation. The class's introductory comment also understates some later coupon/download/dropship behavior; rely on the reviewed method body and tests rather than assuming all source prose is current.

Order states and allowed transitions are declared in [app/Models/Order.php](https://github.com/liberusoftware/project-ecommerce-laravel-filament/blob/af5a2b29c9c26ba89c97b9daccbb3facf20a8c2f/app/Models/Order.php). The transition graph includes payment, supplier, fulfillment, cancellation, refund, and partial-refund states. A presentation adapter should call the authorized action and display its result rather than submit an arbitrary status field or assume every state can transition to every other state.

## Tenant, store, and presentation boundaries

Store selection and permission checks are separate concerns. [app/Services/StoreContext.php](https://github.com/liberusoftware/project-ecommerce-laravel-filament/blob/af5a2b29c9c26ba89c97b9daccbb3facf20a8c2f/app/Services/StoreContext.php) controls store-scoped reads and write context. Its `writingTo()` helper expects the caller to have checked ownership; it is not itself an authorizer. [app/Support/StoreAccess.php](https://github.com/liberusoftware/project-ecommerce-laravel-filament/blob/af5a2b29c9c26ba89c97b9daccbb3facf20a8c2f/app/Support/StoreAccess.php) evaluates platform privileges and team permissions. Queued/console paths need an explicit review of their context because the store-scoping behavior differs from a storefront request.

Filament has separate administrative and merchant surfaces under `app/Filament/Admin` and `app/Filament/App`, with panel composition in [app/Providers/Filament/AdminPanelProvider.php](https://github.com/liberusoftware/project-ecommerce-laravel-filament/blob/af5a2b29c9c26ba89c97b9daccbb3facf20a8c2f/app/Providers/Filament/AdminPanelProvider.php) and [app/Providers/Filament/AppPanelProvider.php](https://github.com/liberusoftware/project-ecommerce-laravel-filament/blob/af5a2b29c9c26ba89c97b9daccbb3facf20a8c2f/app/Providers/Filament/AppPanelProvider.php). Existing application views and Livewire components should be mapped during extraction rather than discarded when a package folder is absent. React, Next.js, Nuxt, and mobile plans remain useful target adapters; source inventory does not certify that every planned adapter is present.
