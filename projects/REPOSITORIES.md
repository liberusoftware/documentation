# Project repositories by presentation

Choose the product and the delivery boundary separately. Each product has one repository per presentation. New shells derive from the matching Boilerplate foundation; the existing Filament applications retain their source and module composition. The new skeletons provide application structure and build configuration, not feature parity or completed product/API integrations.

| Presentation | Boilerplate | Application boundary |
| --- | --- | --- |
| Laravel · Filament | [Start here](https://github.com/liberusoftware/project-boilerplate-laravel-filament) | PHP/Composer Laravel host with Filament panels |
| Laravel · Inertia · Vue | [Start here](https://github.com/liberusoftware/project-boilerplate-laravel-inertia-vue) | Laravel routes and sessions with Vue pages over the Inertia protocol |
| Laravel · Inertia · React | [Start here](https://github.com/liberusoftware/project-boilerplate-laravel-inertia-react) | Laravel routes and sessions with React pages over the Inertia protocol |
| Nuxt · Vue | [Start here](https://github.com/liberusoftware/project-boilerplate-nuxt-vue) | Independent Vue application with Nuxt server rendering and reviewed API integration |
| Next.js · React | [Start here](https://github.com/liberusoftware/project-boilerplate-next-react) | Independent React application with explicit Next.js server/client boundaries |
| React Native · Expo | [Start here](https://github.com/liberusoftware/project-boilerplate-mobile-react) | Native iOS/Android application using React Native and Expo |
| Flutter · Mobile | [Start here](https://github.com/liberusoftware/project-boilerplate-mobile-flutter) | Flutter iOS/Android application using Dart and mobile widgets |

## Initialize a new application

Use the layer's Boilerplate repository as the GitHub template. Replace the owner/project values and use a repository name appropriate to the intended product:

```bash
gh repo create YOUR-OWNER/YOUR-PROJECT --template liberusoftware/project-boilerplate-next-react --private --clone
cd YOUR-PROJECT
```

For another presentation, select the corresponding Boilerplate slug from the table. Cloning a named product skeleton is appropriate when you want that product's documentation and composition entry points. Follow its README, `AGENTS.md`, declared toolchain and committed locks. The user-facing name, application/bundle IDs and environment configuration must be set for the deployment; a GitHub rename does not change package or store identities.

| Surface | Initialize and check |
| --- | --- |
| Laravel + Inertia | Copy `.env.example`; `composer install`; `npm ci`; generate a new local application key; configure a new local database; `php artisan migrate`; `php artisan test`; `npm run typecheck`; `npm run build` |
| Existing Laravel + Filament | Follow the preserved application README and actual Composer/npm scripts; select compatible core and Filament modules through documented lifecycle hooks |
| Next.js | Copy `.env.example` to `.env.local`; `npm ci`; `npm run lint`; `npm run typecheck`; `npm run build`; `npm run dev` |
| Nuxt | Copy `.env.example` to `.env`; `npm ci`; `npm run typecheck`; `npm run build`; `npm run dev` |
| React Native + Expo | `npm ci`; `npm run lint`; `npm run typecheck`; `npm run export`; `npm start`; configure native IDs and use a reviewed development/release build for real devices |
| Flutter / Dart mobile | Use `.flutter-version`; `flutter pub get`; `flutter analyze`; `flutter test`; `flutter run -d <device-id>` |
| Dart desktop | Use `.flutter-version`; install native tools for the target OS; `flutter pub get`; `flutter analyze`; `flutter test`; `flutter run -d linux`, `macos` or `windows` |

Generate keys only for a new local application. Never replace a production application key as part of setup. Inertia shares Laravel routes/session middleware; independent web and device clients use reviewed APIs. Keep tenant authorization and domain transitions authoritative in Laravel. The Dart desktop/mobile repositories use Flutter native hosts and remain independent applications with separate platform configuration.

For complete layer instructions, use the [presentation runbooks](../guides/presentation/README.md), including [Dart desktop/mobile](../guides/presentation/DART.md). Independent modules retain Composer, npm or pub manifests appropriate to their runtime. A repository is not a registry publication, and a declared framework peer is not proof of implemented behavior.
